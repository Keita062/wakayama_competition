## 5. 目的を叶えるための方法

### 方法

> ## 分析から政策提言までを行う。

**理由：** 目的を叶えるには、**データドリブンで幸福度を向上させる施策が何なのかを明確にし、手を打つこと**が必要だからです。施策が明確になっていなければ手は打てず、手を打たなければ幸福度は上がりません。したがって、分析だけでも提言だけでもなく、**分析から政策提言までを一続きで行うこと**を方法とします。

### この方法をとった後の状態

分析から政策提言までを終えたとき、次の4点を言える状態になっていることを目指します。

| # | 言えるようにすること | それが言えると何ができるか |
|---|---|---|
| **1** | **どの分野に手を打つべきか**（優先順位と、その根拠） | 予算を振り向ける先が決まる |
| **2** | その分野は、**周知・運用で実感を上げられるのか／環境そのものを変えないと上がらないのか** | 打つべき施策の型（ソフト／ハード）が決まる |
| **3** | 環境を変えるなら、**どの指標を、どこまで動かすのか** | 施策のターゲットと目標値が決まる |
| **4** | その打ち手で、**幸福度がどれだけ動くと見込めるのか** | 費用対効果を示して意思決定にかけられる |

この4点が埋まれば、**「和歌山県はここに、こう手を打つべき」**という形で提言に落ちます。逆に、ここが埋まらない設計は目的を達成しません。

## 6. 収集するデータ

### 6-1. 使うデータ

> ## デジタル庁「地域幸福度（Well-Being）指標」ダッシュボード

**市区町村単位**で、**住民の実感（主観指標）と地域の環境水準（客観指標）が、同じ24分野の枠組みで並んで取れる**のがこのデータの特徴です。全国約530自治体分が公開されています。

### 6-2. このデータで何が分かるか

| 取れるもの | 分かること |
|---|---|
| **幸福度**（0〜10の総合スコア） | 住民が全体としてどれだけ幸せを感じているか。**これを目的変数にする** |
| **主観24分野**（住民の実感） | 24分野それぞれについて、住民が実際にどう感じているか |
| **客観24分野**（環境の水準） | 同じ24分野について、地域の環境が客観的にどの水準にあるか |
| **客観の個別KPI**（208本） | 客観24分野が、どの具体的な指標から成り立っているか |

主観と客観が同じ枠組みで並ぶため、**「環境はあるのに、住民の実感が伴っていない分野」を特定できます。** これが本分析の起点です。

**24分野の内訳**

- **生活環境（16）**：医療・福祉／買物・飲食／住宅環境／移動・交通／遊び・娯楽／子育て／初等・中等教育／地域行政／デジタル生活／公共空間／都市景観／自然景観／自然の恵み／環境共生／自然災害／事故・犯罪
- **地域の人間関係（2）**：地域とのつながり／多様性と寛容性
- **自分らしい生き方（6）**：自己効力感／健康状態／文化・芸術／教育機会の豊かさ／雇用・所得／事業創造

### 6-3. データの出所

| 区分 | 出所 |
|---|---|
| **主指標（主観）** | **すべて住民アンケート。** デジタル庁が全国の自治体で実施 |
| **環境変数（客観）** | **官庁統計から合成。** 国交省「都市モニタリングシート」、厚労省「医療費の地域差分析」、総務省「社会・人口統計体系」等。**原出典まで公開されている** |
| **統制用の外部データ** | 総務省（人口・高齢化率・財政力指数） |

### 6-4. 目的変数と分析単位

| 項目 | 内容 |
|---|---|
| **目的変数** | **幸福度**（0〜10の生値）。コンペのテーマ名に一致させる |
| **説明変数** | 主観24分野・客観24分野（いずれも偏差値）、客観の個別KPI（実数） |
| **分析単位** | **1行 ＝ 1自治体 × 1年度** |
| **対象** | **推定は全国の自治体、診断の対象は和歌山。** 全国データで「同水準の自治体ならこのくらい」という物差しを作り、それを和歌山に当てる |

## Appendix. 検討して採らなかった案

設計を組む過程で検討し、採用しなかった案とその理由です。

| 採らなかった案 | 理由 |
|---|---|
| 相関係数ランキングで寄与を出す | 2変数間の関係しか見えず、他分野の影響を排除できない（多重共線性の事前チェック用途に留める） |
| 通常の重回帰で係数を読む | 24分野が互いに強く相関しており、多重共線性で係数の符号が反転する |
| ドミナンス分析 | 全部分集合の探索が 2²⁴ ≒ 1,677万通りとなり計算できない |
| 主成分回帰 | 分野名に戻せず、提言に落ちない |
| ランダム分割の交差検証 | 同一自治体の複数年度が訓練/検証に分かれて漏洩する（GroupKFold を使う） |
| 24分野を行内で順位化して差を取る | 単位も意味も違う24分野を、1本の順位軸に並べる根拠がない |
| 優先度スコア＝相関係数 × 差 | 相関係数と偏差値ポイントを掛けても、単位のある量にならない |
| 残差ランキング上位を「お手本自治体」にする | もともと恵まれていた自治体が並び、参照先にならない |
| 客観KPIに自分たちで閾値を決めて判定する | 閾値の根拠が主観になる |
| オープンデータに現れない潜在変数を説明変数に入れる | 観測値がない変数は列として立てられず、係数も重要度も定義できない。時間で変わらない自治体固有の条件は年度差分で、全自治体共通の要因は年ダミーで落とせるため、列挙する必要もない |
